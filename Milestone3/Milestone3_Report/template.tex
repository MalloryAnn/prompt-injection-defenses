\begin{abstract}
Prompt injection is a growing security risk for applications that use large language models (LLMs), especially systems that combine trusted instructions with untrusted user or retrieved text. To prevent Prompt Injection's many companies implement tools like Prompt Injection Scanners that will detect malicious content like this. 

Although a great tool, it is not fully reliable when used alone. So we conducted a case study evaluating similar tools, where we observed distinct differences in Rebuff, Vigil, and Prompt Injection. Rebuff relies on a heuristic scoring mechanism that proves effective at flagging both obvious and borderline threats by evaluating risk against a defined threshold. In contrast, Vigil utilizes a YARA-based framework that offers high transparency and precision for established attack signatures, though it struggled with subtle inputs that fell outside its predefined rule set. Along with that, Prompt Injection focuses solely on detecting and filtering malicious input. Comparing these tools revealed that, when used alone, they can be considered weak, but working together they form a stronger prompt injection tool. 

Thus, we developed a multi-layer detection pipeline that integrates a heuristic layer inspired by Rebuff with the machine learning classifier from PromptInjection. Our experimental results indicate that this ensemble approach significantly bolsters detection robustness by compensating for the specific limitations of each individual method. For instance, while the heuristic component efficiently identifies explicit keyword-based threats, it often overlooks nuanced prompts, that lack obvious indicators. The PromptInjection model, however, successfully flagged these instances by analyzing underlying intent rather than just surface patterns. By combining these two strategies, the integrated system achieves a broader detection coverage than any single tool, meeting our objective of enhancing and unifying existing frameworks into a more robust defensive solution.
\end{abstract}

\section{Introduction}
Large Language Models (LLMs) are a common use in many modern applications today, while being widely used this can often make LLMs a target of malicious tools, like Prompt Injection. Prompt Injection is a malicious method meant to trick LLMs with malicious inputs that can alter machine instructions and behavior. Although there are many defensive tools to counter this type of injection attack, many of them offer a certain mitigation that can be taken advantage of and bypassed.
To address these limitations, we conducted an evaluation of the Rebuff, Vigil, and Prompt Injection Tools. During this evaluation, we highlighted their complimentary strengths and weaknesses in order to create a stronger tool. Thus, we propose a multi-layer detection pipeline that combines heuristic analysis from the rebuff tool with machine learning classification from the prompt injection tool to overall improve coverage and robustness. 


\section{Task description and data construction}
\label{sec:headings}
We are provided with five datasets from Kaggle: Sales train, Sale test, items, item categories and shops. In the Sales train dataset, it provides the information about the sales’ number of an item in a shop within a day. In the Sales test dataset, it provides the shop id and item id which are the items and shops we need to predict. In the other three datasets, we can get the information about item’s name and its category, and the shops’ name.
\paragraph{Task modeling.}
We approach this task as a regression problem. For every item and shop pair, we need to predict its next month sales(a number).
\paragraph{Construct train and test data.}
In the Sales train dataset, it only provides the sale within one day, but we need to predict the sale of next month. So we sum the day's sale into month's sale group by item, shop, date(within a month).
In the Sales train dataset, it only contains two columns(item id and shop id). Because we need to provide the sales of next month, we add a date column for it, which stand for the date information of next month.
